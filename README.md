# Казино-симуляция с непредвиденными событиями

## Описание
Интерактивная симуляция казино с игроками и гусями, где случайные события влияют на ход игры.
В симуляции реализованы различные события: атаки гусей, ставки в казино, кража фишек, саботаж, бонусы и многое другое.
Проект построен по принципам Clean Architecture с разделением на слои: [entities](https://github.com/moonshyXD/UserCollections/tree/main/src/entities), [usecases](https://github.com/moonshyXD/UserCollections/tree/main/src/usecases), [controllers](https://github.com/moonshyXD/UserCollections/tree/main/src/controllers), [adapters](https://github.com/moonshyXD/UserCollections/tree/main/src/adapters).
Все логи симуляции записываются в файл `casino.log`(в .gitignore, инициализируется при запуске приложения) с подробной информацией о балансах, событиях и ошибках.

## Зависимости

Для установки зависимостей для разработчика выполните команду:
```bash
make setup
```

## Основные используемые библиотеки

В проекте использовались следующие библиотеки:
- **questionary** — интерактивное меню в командной строке
- **random** — генерация случайных событий

## Список событий симуляции

| Событие | Описание |
|---------|----------|
| **attack** | Военный гусь атакует случайного игрока, нанося урон 1-100 фишек |
| **honk** | Гусь кричит: если громкость ≤50, оглушает игрока (-10 фишек), иначе оглушает другого гуся и выбывает |
| **steal** | Гусь крадёт 1-100 фишек у случайного игрока |
| **bet** | Игрок делает ставку с множителями: x0 (30%), x0.5 (40%), x1 (10%), x2 (10%), x3 (9%), x10 (1%) |
| **sabotage** | Балансы всех игроков и гусей перемешиваются случайным образом |
| **freebet** | Случайный игрок получает 50 бесплатных фишек |
| **fruit_party** | Игрок проигрывает все фишки в слоте Fruit Party |
| **flock_steal** | Стая военных гусей (1-N) крадёт фишки у игрока и делит между собой |
| **bonus_rain** | Дождь бонусов: 1-N случайных игроков получают 10-100 фишек |

## Основные команды CLI

| Команда | Описание |
|---------|----------|
| **Запустить симуляцию** | Запуск N случайных событий с опциональным seed |
| **Добавить игрока** | Создание игрока с именем и начальным балансом |
| **Добавить гуся** | Создание WarGoose или HonkGoose с именем и громкостью (1-100) |
| **Удалить игрока** | Удаление выбранного игрока из казино |
| **Удалить гуся** | Удаление выбранного гуся из казино |
| **Очистить коллекции** | Очистка всех данных или отдельных коллекций |
| **Посмотреть коллекцию** | Просмотр игроков, гусей, балансов или истории транзакций |
| **Выход** | Завершение работы программы |


## Руководство по запуску

Склонируйте Github репозиторий командой:
```bash
git clone https://github.com/moonshyXD/UserCollections
```

Перейдите в папку с репозиторием:
```bash
cd UserCollections
```

Установите [зависимости](https://github.com/moonshyXD/UserCollections?tab=readme-ov-file#%D0%B7%D0%B0%D0%B2%D0%B8%D1%81%D0%B8%D0%BC%D0%BE%D1%81%D1%82%D0%B8)

Активируйте виртуальное окружение:
```bash
source .venv/bin/activate
```

Для успешного запуска программы следует прописать в командной строке команду:
```bash
make run
```

ИЛИ

```bash
uv run main.py
```

## Тестирование

Запустите виртуальное окружение, если оно до этого не было включено командой:
```bash
source .venv/bin/activate
```

Для запуска тестов программы в пропишите в командной строке команду:
```bash
pytest
```

```bash
make testcover
```

## Ошибка 1 - Off-by-one в цикле событий

Место: [casino.py, метод run_simulation]()

Симптом: пропуск последнего события в выводе

Как воспроизвести: запустить симуляцию

Отладка: Установлен breakpoint на вывод ```print(f"\nСобытие {step}/{steps}")```. Видно, что последнее событие не выводится

Причина: Использовано неверное количество итераций в цикле

Исправление: количество итераций steps в условии цикла увеличено на 1

Проверка:
Поведение симуляции соответствует ожидаемому

## Ошибка 2 - Не вызвана валидация для громкости гуся

Место: [goose.py, метод honk_volume]()

Симптом: недействующее ограничение на громкость гуся

Как воспроизвести: создать гуся с громкостью < 1 или > 100, просмотреть коллекцию гусей

Отладка: Установлен breakpoint на вывод ```self.honk_volume = honk_volume```. Видно, вводимая громкость гуся может быть любой

Причина: не используется никакой метод валидации данных для громкости гуся

Исправление: создание декоратора-валидатора в [entitites/validators.py]() validate_honk_volume для метода honk_volume при инициализации гуся

Проверка:
